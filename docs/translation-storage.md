# 翻译资料与本机启动依赖

## 保存位置

新增引擎和验证脚本必须遵循[新引擎接入与目录生成开发规则](architecture/engine-integration-rules.md)。

人物名提取、自动译名表、正文注入与新引擎接入约束见
[自动人物译名流程与引擎接入规范](architecture/character-glossary.md)。

默认文本根目录是代码项目外的 `translations/`。可在翻译页选择其他独立目录，
或使用 `NAGI_TRANSLATION_OUTPUT_ROOT`；旧变量 `NAGI_QLIE_WEB_OUTPUT_ROOT` 仍兼容。

```text
工作目录/
├─ nagi/                         GitHub 中的源代码
├─ translations/
│  ├─ QLIE/游戏名-安装标识/translation-任务编号/
│  ├─ YU-RIS/游戏名-安装标识/translation-任务编号/
│  ├─ KiriKiri/游戏名-安装标识/translation-任务编号/
│  ├─ RenPy/游戏名-安装标识/translation-任务编号/
│  └─ TyranoScript/游戏名-安装标识/translation-任务编号/
└─ playable/
   └─ 引擎/游戏名-安装标识/
      ├─ 启动测试版.cmd
      ├─ 启动正式版.cmd
      ├─ translation-test/      部分翻译或旧开场试译
      └─ translation-formal/    全文翻译
```

同一引擎的版本共用一个引擎目录，版本写在提取记录中；不同安装路径和文本任务不互相覆盖。
`playable` 位于所选文本根目录的同级，而不是代码仓库或原游戏中。
可玩版本的 `game/`、`runtime/`、`deployment.json`、`启动汉化版.cmd` 等文件直接放进
`translation-test` 或 `translation-formal`，不再嵌套 `localized-game-编号`。
游戏根目录只生成 `启动测试版.cmd` 和 `启动正式版.cmd`，分别固定指向对应版本，
不再生成通用的“启动汉化版”入口。启动文件使用相对路径，内部依赖无需移动到游戏根目录。
这套规则由 QLIE、YU-RIS、KiriKiri、Ren'Py 和 TyranoScript 共用的部署流程执行；后续引擎也沿用相同的任务、测试版和正式版目录。
引擎适配只处理资源格式和运行组件，不另建引擎专用的顶层部署或验证目录。
开发验证在系统临时目录中使用同一套目录规则，不改写正式任务的输出路径；
需要保留的验证截图、报告和维护备份收在本机状态目录的 `maintenance/` 下，不放在工作目录顶层。
目录规则一致不代表尚未适配的引擎或游戏版本已经可以回包。

同类版本再次生成时，先完整生成并校验临时副本，成功发布前将原有版本（含其存档）移至
`playable/.history/引擎/游戏名-安装标识/`，再换入新版本；不直接删除旧版。
若发布失败会尝试还原原目录，不会将半成品作为启动入口。文本和 API 返回仍按任务保存。

YU-RIS 提取只保存 `source/texts.json` 与必要的 `extraction.json`。
不保存解包的 `.ybn` 或重复的原始 `.ypf`，翻译/回包时从原游戏读取并比对哈希。
原始游戏因此必须保留；原包改变时停止，不会带着旧定位信息继续付费翻译。
翻译目录保留 `translations.json`、真实 API 返回、失败返回以及断点/完成记录；
成功返回只保存一份，不重复保存可重建的请求文本。
资源包、中文映射和字体桥接只在点击第三步时生成，放进 `playable` 的独立副本。

新任务在语料目录保存 `characters.json`。第二步付费确认后，先自动翻译全部登记人物名，
再翻译所选正文，无需人工审核。人物译名保存在游戏级 `character-glossaries/` 缓存和任务快照中。
部分翻译只选开场剧情前 50 条对白/旁白，人物名是独立预翻译范围；符合身份与版本的译名表可以复用。
现有旧任务继续采用原请求，不会被自动重译或覆盖。

YU-RIS 回填时区分人物识别键与姓名栏显示文字：保留 `ES.CHAR.NAME` 的识别键，
姓名栏使用独立的显示名译文；台词前缀恢复为原识别键及游戏登记的分隔符。
因此 API 把姓名译成变体、加冒号或改用中文引号时，不会让姓名落入正文。
仅处理原文中能与登记人物匹配的台词，不将旁白中的引用误判为人物名；
无法确认姓名/正文边界时停止回填，不静默丢弃文字。原文和 API 返回文件保持不变。

第二步可选“部分翻译”“全文翻译”，已有完整全文结果时还可主动选择“查缺补漏”。查缺补漏只重新提交含日文假名且译文与原文完全相同的条目，独立保存补翻回执，全部返回后再合并到原全文结果；它不会成为普通翻译或发布流程的自动质量门槛。新部分翻译沿新游戏的主剧情入口选择前 50 条对白/旁白，
不按资源包顺序或文件名排序，不计系统提示、日期、控制命令及独立姓名字段。
剧情结束时不足 50 条则选择全部；遇到无法确定的入口、动态跳转或分支时停止并提示，不能猜测路径。
输出放在新的 `partial-编号/`，全文仍放在 `full-编号/`。
YU-RIS 计划/结果中的 `opening_selection`、QLIE 的 `opening-selection.json` 保存规则版本及有序 ID；
没有新标记的旧任务继续使用原提取顺序，已有可玩版不自动重建。
详见[开场剧情选取规范](architecture/opening-selection.md)。
YU-RIS 部分翻译回包只替换所选文本，其余原文及控制流程保留。切换范围不会覆盖旧结果，
断点续跑与后端重启也不会将部分翻译扩大为全文。

QLIE 的文本脚本、文本语料和回填结构记录仍用于现有翻译流程，不会提取图像或音频作为翻译输出。
运行记录、来源编号、哈希和断点是必要元数据，不是可直接删除的杂项。
旧格式任务、旧可玩版的自带组件继续兼容；移动旧任务时必须同步修改恢复记录，不能只改目录名。

## Locale Emulator

1. 从 [上游发布页](https://github.com/xupefei/Locale-Emulator/releases) 获取并解压完整组件。
2. 在 Nagi → 视觉小说翻译 → 第三步中选择本地目录，点击“检查并保存目录”。
3. 选择时只读取目录、检查 Windows 文件格式并记录组件哈希，不执行、不安装、不下载软件。
4. 生成新汉化版时会检查所选目录，并为游戏生成独立 `.exe.le.config`（ja-JP、东京时区、不强制管理员）。
5. 启动器使用 `LEProc.exe -run`，不依赖用户全局配置中的特定 GUID，也不把 LE 二进制文件复制到源码或新汉化副本。

路径和组件哈希存于 `.nagi/web/locale-emulator.json`，由 Git 忽略。
更新或移动 LE 后，应重新选择并保存；新版启动器每次读取当前本机配置。
组件检查不等于真实性或所有版本兼容性认证，请只选择信任的上游发行物。
原型中已生成的旧汉化副本继续使用自带的已校验组件，不强制迁移或覆盖。

Locale Emulator 只用于需要日区环境的 Windows 游戏启动，不用于文本提取、API 调用；
缺少它不会阻止前两步。仍需 Windows、Nagi Python 环境及可选 `deployment` 依赖（Frida）。
第三步的引擎/游戏兼容范围没有因目录规则统一而扩大，当前限定于已验证的 QLIE FilePack 3.1 和 YU-RIS 479 游戏配置。

## 发布到 GitHub

提交 Nagi 源码、测试和使用文档，不提交游戏、文本、API 返回、密钥、本机配置或第三方二进制文件。
不用把 LE 打进 GitHub 仓库。使用者自行下载并选择本地目录即可。
如未来另行制作包含 LE 的安装包，需要审查其 LGPL-3.0、相关组件许可、版权声明和对应源码提供要求；
参见 [上游许可说明](https://github.com/xupefei/Locale-Emulator#license) 与 `THIRD_PARTY_NOTICES.md`。
