# 更新与旧数据兼容

更新前先在网页停止任务、等待保存，然后退出 Nagi 服务。建议备份配置与任务目录。
不要将新程序 ZIP 直接覆盖旧游戏或使用中的运行时。

## 目录职责

| 目录 | 内容 | 更新策略 |
| --- | --- | --- |
| 程序目录 | runtime、网页资源、启动入口、许可证 | 新版从干净 ZIP 解压 |
| data/.nagi | API 设置、工作台记录、缓存、用户配置版本 | 保留，不能从发行包覆盖 |
| 工作区/.nagi | 对应工作区的会话、memory、run、MCP 配置 | 保留原位置 |
| translations/引擎/游戏/任务 | 原文、人物译名表、译文、checkpoint、workflow.json | 保留，不自动重译 |
| playable/引擎/游戏 | 测试版、正式版、存档及版本入口 | 保留，不用程序更新覆盖 |

便携版默认所有数据位于程序目录下 data，含 translations/playable。
源码版默认配置放项目 `.nagi`，文本与可玩版继续使用项目相邻的 translations/playable；
wheel 安装默认用户 LocalAppData/Nagi（其他平台为 ~/.local/share/Nagi）。
`NAGI_DATA_DIR` 或启动器的目录选择优先。程序和数据可以完全分开。
只读程序目录时，目录指针保存在 `%LOCALAPPDATA%/Nagi/locations`；移动只读介质后请重新选择。

推荐把数据放程序之外：退出旧版，解压新版，在新版选择**同一个数据目录**后启动。
如果旧版使用包内 data，可将整个 data 复制到新目录，再选择它；原目录保留作备份。
不要覆盖、删除或合并同名游戏存档。要继续使用已有副本，运行其“重新定位Nagi.cmd”。

## 从旧名称升级

Python 导入改为 `from nagi import Nagi`，命令改为 `nagi` 或 `python -m nagi`。
没有继续公开旧包别名。旧 `.pico` 与 `PICO_*` 仅用于兼容已有用户数据：
同一个工作区没有 `.nagi` 但存在 `.pico` 时，直接使用旧目录，**不复制整个私人目录、
不改写会话与翻译正文、不删除旧记录**。若两者都有，以 `.nagi` 为准，不自动合并。
新配置使用 NAGI_*；同一项新变量优先于旧变量。新版 `data-version.json` 的 schema_version 为 1；
模型设置缺少版本字段视为版本 1，保存时补齐。未知版本拒绝覆盖，应回到适配的新程序。

Windows DPAPI 密钥不能跨用户或电脑解密。界面会提示重新输入；不会降级成明文存储。
只复制公开程序文件不会带走密钥。`.env` 和自定义 MCP 配置也属于私人数据。

## 旧路径失效

配置、会话及 workflow.json 中的旧路径不会被字符串批量改写。若游戏、译文或旧源码目录
被移动，恢复失败会在页面“使用说明”显示，保留原任务、人物表与译文。
可先将相关目录恢复到记录中的原路径，重启继续任务；或作为新任务重新选择目录。
新建任务不等于继续旧任务，不会在后台自动重译。需要批量迁移历史任务时应先备份，
另行核对哈希与各级目录关系；本版不提供绕过校验的任意路径重写。

新生成的可玩副本提供重新定位入口。旧版硬编码 Python 的启动器可用
`python -m nagi.game_launcher repair "可玩副本目录"` 更新：先校验部署清单和运行时文件，
保留旧启动文件备份，仅更新启动模板及配置引用，不碰游戏资源与存档。
旧测试版、正式版及 `.history` 不会因更新 Nagi 被清空。
