# 自动人物译名流程与引擎接入规范

状态：已接入 Nagi 网页工作台的 QLIE、YU-RIS 479 翻译流程。

## 目标与范围

新引擎必须遵循：提取明确人物信息 → 自动统一人物译名 → 正文携带相关译名 → 回填保护引擎绑定。
人物译名以所选模型的有效返回为准，不设置人工检查或审核步骤。

人物译名属于确定性检索的专用参考通道，不能仅依赖普通 RAG 的相似度匹配。
QLIE 继续使用既有剧情片段 RAG；YU-RIS 新增人物译名参考，不因此宣称已具备完整剧情检索。
QLIE 的独立译文脚本可在第三步回包并启用 Unicode 中文字体；QLIE 和 YU-RIS 的可玩部署均限于已验证游戏配置。

## 第一步：提取人物，不调用 API

公共适配入口：`nagi/gameio/characters.py`。
适配器只读解析脚本，发布原有文本语料和 `characters.json`。
必须依赖明确角色登记、姓名字段或说话者标记，不能把所有短词猜成人名。

### 共同数据契约

目录表包含：

- `schema_version`：当前为 1。
- `engine`：引擎族，如 QLIE、YU-RIS。
- `source_sha256`：完整源语料摘要；YU-RIS 使用原脚本包，QLIE 使用 `segments.jsonl`。
- `characters`：去重、稳定排序的人物列表。
- `bindings`：原始文本记录编号到人物 ID、字段角色的映射。
- `catalog_sha256`：以上字段的确定性摘要。

人物记录包含 `id`、`lookup_name`、`source_name`、`aliases`：

- ID 由引擎与原始识别名生成，不依赖译名。
- `lookup_name` 是引擎识别名，不能让正文模型随意改写。
- `source_name` 是原始姓名栏显示名，也是人物预翻译的主要输入。
- 别名仅来自脚本明确绑定，不猜测昵称、读音、性别、身份或人物关系。

绑定角色为 `lookup`、`display`、`dialogue`。同一识别名对应不同显示名而适配器无法消歧时，
明确拒绝，不任取一个译名。没有人物时发布空目录表，不调用人物 API，也不阻止正文翻译。

### 两个现有引擎

- **YU-RIS**：解析 `ES.CHAR.NAME`，其中 `PSTR` 是识别名、`PSTR2` 是显示名；
  根据 `ES.CHAR.NAME.MARK.SET` 的分隔符，为能明确匹配的 `WORD` 台词绑定人物。
  不改变原有 `texts.json` 的 ID、顺序或原文，人物信息放入旁路目录表。
- **QLIE**：不假定所有版本有统一登记表。当前从解析器已确认的 `speaker`、`speaker_name`
  信息汇总人物，例如 `〖姓名〗` 和随后关联的台词。原 `segments.jsonl` 保持原有定位信息。

已提取的旧语料可以在第二步用同一适配器补建目录表，不能改动原始文本。

## 第二步：先统一译名，再提交正文

公共调用：`nagi/translation/characters.py::prepare_glossary`。
只有用户确认第二步 API 费用、且原始语料完整性校验通过后，才允许调用。
提取、查看任务及重启恢复不能触发模型。

部分/全文翻译都先准备全部已识别人物。新部分翻译的正文限于开场剧情前 50 条对白/旁白；
不足时取全部。选取遵循[开场剧情选取规范](opening-selection.md)，不是资源包排列顺序。
人物名属于独立范围，不占用或扩大正文配额。页面须在 API 调用前确认费用。

### 自动翻译与失败处理

使用用户本次选定的模型和接口，目标语言为简体中文。每批最多 48 个人物，
人物输入记录 JSON 的总长度以 4,800 字符为分批边界；模型返回 `translations` 数组中的 `id`、`text`。
同一人物 ID 只能返回一个非空译名。

仅校验完整 ID 集合、重复、字符串类型、非空、长度和控制字符，不做人工作业或语义评分。
日文人名读音不一定能由登记文字唯一确定，有效模型返回就是本次统一译名。
格式异常有上限地重试；名字阶段失败或取消时，不提交正文。

### 保存与复用

常规工作台布局：

```text
translations/引擎/游戏名-安装标识/
  character-glossaries/缓存标识/
    character-glossary.json
    0000.response.json
    .lock
  translation-任务编号/
    source/characters.json       # YU-RIS 的语料目录
    corpus/characters.json       # QLIE 的语料目录
    full-编号/ 或 partial-编号/
      character-policy.json
      character-glossary.json
      正文 API 返回与译文
```

两个语料目录按引擎选择，不是重复输出两套。旧版单任务入口使用对应任务附近的缓存，
身份仍包含游戏安装路径摘要，不能串用不同游戏。

缓存身份包括游戏、人物目录表、供应商、模型、接口、协议、目标语言和人物提示词版本。
短目录名只是路径标识，文件内部校验完整身份，以兼顾 Windows 路径长度限制。
没有 API 密钥；目录表、快照、缓存和译文都是本机用户数据，不上传 GitHub。

API 原始返回先持久保存为 received 日志，解析成功后发布回执。恢复时复用已保存的有效结果，
不重复支付成功批次；失败回执保留。网络断开且本地未收到返回时，不能保证供应商尚未计费。
共享缓存用操作系统文件锁防止并发重复调用，进程退出后锁自动释放。

任务快照版本为 `names_v1_...`，由目录表、请求身份和实际译名共同决定。
同游戏同配置的测试/正式任务复用结果；改变游戏、模型、接口、源目录表或策略会产生新版本。
快照和旧译文不能原地覆盖。已有新流程正文任务却缺失人物快照时，停止并要求恢复或新建任务，
不能先重新付费翻译名字，再与旧正文混用。

### 注入正文请求

- 显式说话者或姓名字段通过 `bindings` 必定携带对应译名。
- 原文中出现已知原名或明确别名时，按文字匹配附上人物条目。
- 单字名（例如“将”）只在明确人物绑定时激活，不在普通句子中做子串人物识别。
- 不合并近似名字、不虚构别名、不对整段译文做全局替换。

QLIE 把命中名字作为 mandatory `terminology` 加入现有请求，即使普通 RAG 预算为零也保留。
译名版本进入计划、请求、翻译缓存和检索索引身份。
YU-RIS 请求增加 `character_glossary`，包含本批人物和字段绑定；批次拆分重试沿用同一快照。
正文人物称呼由模型遵循译名表处理，不能承诺字面匹配完全解决所有语境歧义。

## 第三步：姓名回填与识别键保护

- 检查正文结果绑定的译名版本与任务快照一致，缺失或篡改则停止。
- YU-RIS 保留识别名和原姓名分隔符，姓名栏 `PSTR2` 使用统一译名。
  部分翻译也回填已经单独翻译的人物显示名；未选中的正文保持原文。
- QLIE 的明确 `speaker_name` 字段从译名表构建，保留括号/标签，不把姓名添加到台词正文。
- 原始 API 返回保持原样，回填修正不能伪装成模型原始返回。
- 不覆盖原游戏或存档；可玩版本仍遵守测试/正式目录和旧版归档规则。

## 旧任务兼容

已经有旧正文计划或回执的任务按原请求继续，不在中途增加名字 API 调用。
YU-RIS 看正文计划是否有 `character_glossary_version`；QLIE 看已有 `translation-run` 是否伴随
新流程的 `character-policy.json`。新建翻译任务才使用新流程，不能宣称旧译文已采用新译名表。
后端恢复只读快照及状态，不加载密钥、不调用 API。

## 新引擎接入检查清单

目录、部署入口、旧版归档及开发验证同时遵循[新引擎接入与目录生成开发规则](engine-integration-rules.md)。

1. 编写只读人物适配器，提供登记名、显示名、可证明别名、记录绑定和完整源语料摘要。
2. 第一步发布共同 `characters.json`，保留原始记录 ID、顺序和回填定位信息。
3. 在付费确认与源校验后调用共同 `prepare_glossary`，等全部人物准备好再提交正文。
4. 使用共同精确检索接口注入当前人物译名，不能只存文件而不进入请求，也不能被普通 RAG 排名挤掉。
5. 请求、缓存、正文结果及部署回执绑定译名版本，不跨游戏、接口或旧版本混用。
6. 回填区分识别键和可见姓名，保留控制流、占位符、原文未选范围及 API 原始返回。
7. 设计旧任务恢复和失败断点策略，不能默默跳过人物预翻译。
8. 无真实 API 的自动测试通过后，才能声明新引擎符合本流程。

必须覆盖：提取不付费、去重与绑定、名字先于正文、无人工审核、返回异常、取消续跑、
已收回执免费恢复、同游戏共享、跨游戏/模型隔离、快照篡改/缺失、零 RAG 预算、
单字误判、未登记昵称、部分翻译独立范围、识别键保护、源文件不变、旧任务兼容。

回归入口：`tests/test_character_glossary.py`、`tests/test_yuris_speakers.py`、
`tests/test_translation_context.py`、`tests/test_partial_translation.py`、`tests/test_yuris.py`。
网页工作台是正式入口；底层只构建请求的离线/诊断函数不自行调用付费 API，
后续新增执行入口也必须先完成本规范的人物预翻译准备。
