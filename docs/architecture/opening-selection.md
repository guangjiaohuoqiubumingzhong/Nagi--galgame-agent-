# 部分翻译：开场剧情前 50 条

## 公共约定

新任务使用 `opening-story-v1`。第一步继续完整提取文本、人物及控制信息，不改变原始 ID 或排列；
第二步在任何付费 API 调用前验证语料，按引擎的新游戏主剧情入口选取最多 50 条对白/旁白。
系统提示、日期、调试内容、资源名、姓名登记/显示字段不占正文配额。
先统一全部人物译名的流程不变；正文请求必须携带匹配的人物译名。

按剧情执行顺序选择，而非资源包顺序、自然文件排序或全文中最先出现的 50 个可翻译项。
剧情真正结束且不足 50 条时翻译已有条目；无法解析的分支、动态跳转、循环或缺失标签必须报错，
不默默改选别的脚本、跳过到后续剧情凑数或扩大为全文。人工选择分支/入口不在当前功能范围内。

## 当前适配

- YU-RIS 479 / ERIS：读取 `YSLB` 标签表，验证版本、边界、重名、脚本/指令目标。
  从 `SCENARIO_MAIN` 主剧情标签出发，按静态 `GO` / 剧情 `GOSUB` 跳转、返回顺序读取 `WORD`。
  不从有标题、读档和附加剧情分支的 `SCENARIO_START` 调度器直接顺扫。
  已有显示/注册宏 `ES.*`、`MAC.*` 不计正文，`ES.SEL.*` 提示路径不确定。
  Case 六花实际路径是 `SCENARIO_MAIN → MC2_01_010 → yst00147.ybn`；花梨的自我介绍是第 3 条。
  无标签表且仅有一个脚本的独立线性故事允许从其起点开始。
- QLIE：遵循当前 AVG 框架的 `Scenario/Root.s` 调度约定，读取静态剧情脚本跳转及标签。
  `AVG/header.s` 的 `@@Top` 包装入口按该框架约定进入 `@@MAIN`，而非把缺失标签任意当作文件起点。
  同名覆盖脚本使用提取清单中已明确的资源加载顺序；没有可靠覆盖顺序时报错。
  单文件独立故事允许直接从起点开始。对白/旁白累计 50 条；途经的 `speaker_name` 单独记录，
  直接复用已付费生成的人物译名表回填，不占正文配额、不重复请求姓名 API。
  未经验证的其他 QLIE 框架入口、控制语法需增加适配，不承诺自动猜出所有游戏的开场。

## 一致性、恢复与存储

YU-RIS 在 `translation-plan.json` 与 `translation-result.json` 中保存 `opening_selection`，
含版本、引擎、入口、配额和有序 `selected_ids`。正文哈希也按该顺序计算。
部署、审计使用同一选取器复算并比对；所选以外的正文保持原样，全部人物显示名仍按词表独立回填。

QLIE 保存 `opening-selection.json`，含正文 `selected_ids` 和独立的 `display_ids`。
正文 ID 顺序绑定到规划配置/批次标识，整份语料仍须通过计数、哈希、双向链接等校验；
RAG 索引仍建立在完整有效语料上，而不是只用选中的 50 条。
预览将正文 API 候选与来自人物译名表的显示名候选一起执行结构校验及回填。

旧部分翻译没有新选取标记时，恢复和部署保留原提取顺序，不能改写其已付费请求或扩大选区。
新开始的部分翻译使用新目录与新计划；旧正式版、测试版及存档不会仅因修改规则而被覆盖。
需用户再次执行第二步（确认 API 费用）和第三步，才能生成新的开场测试版。

## 新引擎接入与回归检查

新引擎必须提供可验证的主剧情入口、稳定文本 ID、剧情跳转解析及有序选择结果。
不修改第一步原文，不允许部署层自行重新切片。新增控制语法须先扩充选取器、失败检查及测试。

重点覆盖：乱序资源包、跨脚本顺序、不可达文本、少于/等于/超过 50 条、系统/姓名排除、
重复或缺失标签、循环/分支拒绝、元数据篡改、付费前失败、旧任务恢复、所选外正文不变、
姓名独立回填，以及真实游戏中的截图句子确实落入开场范围。
参见 `tests/test_opening_selection.py`、`tests/test_partial_translation.py`、`tests/test_character_glossary.py`。
